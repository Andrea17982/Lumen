# Lumen 0.6.0 — Task memory, autonomous Orchestra and code validation

> Historical release notes. For the current product, read [Features](../features.md), [Validation](../validation.md) and the [latest changelog](0.7.0.md).

Lumen 0.6 keeps approved work moving, carries task decisions across agents and long conversations, and connects code changes to diagnostics, affected callers and project tests.

## Added

### Durable, source-linked task memory

- A structured task ledger records the goal, user requirements, decisions and approved scope, current workspace and permission profile, reported work, pending tasks and verification results.
- Facts retain their source message IDs. Assistant statements that tests passed are not treated as verification evidence.
- Ordinary prompts, native CLI continuations, Orchestra workers and integration/review stages receive task context. Category budgets limit prompt growth; complete facts remain retrievable from the app-data context snapshot.
- Task state persists in SQLite and survives application restarts and Compact. Rewind rebuilds it from retained messages. A user-edited handoff is retained as the latest supplied decision.
- Inherited approvals never raise a new conversation's actual permissions. Check evidence is scoped to its workspace, so another project's results do not validate the current folder.
- Explicit `New task:`, `Nuovo obiettivo:` or `/task ` requests can start a new scope without deleting chat history.

### Diagnostics and project validation

- A bounded LSP client reads fresh push diagnostics and negotiated diagnostic-pull responses, reporting file, line, column and error details.
- Default discovery supports installed `rust-analyzer`, `typescript-language-server --stdio` and `csharp-ls`. Other servers, including the Godot editor's GDScript language server, can be configured through `.lumen/diagnostics.json` using stdio or a loopback TCP endpoint.
- The client rejects server-requested edits, ignores explicitly stale document versions and unrelated documents, and limits message size, document count and exchange duration. Externally owned TCP servers are not shut down.
- Missing servers, refused/missing responses, timeouts and incomplete coverage are explicit. Errors already received are preserved when another document times out.
- End-of-turn validation detects actual changes against the turn's Git checkpoint, including new files and edits for which a provider emitted no file event. Unchanged pre-existing work is excluded.
- Relevant headless checks run in their own project directories: Rust compile/tests, JavaScript package typecheck/check/build and unit/test scripts, C# compilation, Go build/tests and Godot resource checks. Existing `LUMEN.md` verification commands remain supported.
- Custom `.lumen/checks.json` checks can opt in with `automatic: true`. Playtests stay manual. Commands run with `CI=true`, bounded output, contained working directories and process-tree cancellation.
- Structured check results are persisted separately from readable verification activity and included in the final verification summary.

### Impact-aware execution and tests

- Structured graph impact includes changed targets, direct/transitive dependents, candidate tests, shared declaration signatures, unknown targets and partial coverage.
- Pre-edit snapshots are merged with current analysis. Deleting or renaming a shared file therefore does not erase its former callers and tests from the validation scope.
- Orchestra workers receive impact information for the files they own, plus relevant project checks. The integrator receives the same contracts and test context. Ownership boundaries still apply.
- Validation considers affected project roots as well as the edited package.
- Graph traversal preserves shortest dependency distances and deterministic ordering. Index format 3 retains nanosecond timestamp precision, and graph cache keys include file sizes.

## Fixed

### Orchestra approval and planning loops

- Clear requests no longer stop at an initial “Agree?” confirmation. Questions are reserved for missing information that changes the result.
- Autopilot moves from preparation to execution without another plan-approval gate. An explicit approval in chat continues the pending Orchestra plan instead of starting a fresh task.
- Preparation now receives the conversation and prior decisions, rather than only a short follow-up such as “proceed” and “Agreed”. Workers, plan audits, integration, conflict resolution and final reviews retain the agreed scope.
- The temporary restriction on editing during preparation is distinguished from the requested implementation and its execution permissions. Implementation requests are not intentionally decomposed into another round of research-only plans.
- A folder change or upgrade from read-only permissions refreshes stale preparation before applying changes, retaining the user's execution authorization. Real unanswered questions are not silently answered by a generic approval.
- A writable Orchestra run without a Git repository reports the missing prerequisite instead of silently becoming a read-only run.
- Worker prompts identify their actual isolated execution folder, even when the conversation mentions the original repository by absolute path.

### Conversation working directory

- `/workspace "absolute directory"` and supported explicit English/Italian directory directives bind the conversation to the new canonical directory before planning, attachments and tools use it.
- Folder corrections entered on an Orchestra clarification card follow the same path.
- The active folder, registered project identity and frontend state update together. Native CLI continuation and graph tools use the correct root.
- Merely mentioning a path in a reference, quote, attachment or fenced document does not switch the workspace. Invalid or ambiguous directives fail explicitly.
- A live conversation cannot change its root while its tools are running. Plans and interrupted work are checked against the root where they were prepared.
- Project notes, relative outputs and pasted-log spill files follow the new workspace rather than the previously selected project.

## Behavior changes

- **Self-healing off now means no automatic corrections; validation still runs.** With it enabled, Lumen performs at most three corrections, each followed by a new validation.
- **Known validation failures leave an error state.** A run is no longer marked successfully complete merely because the writer stopped after an unsuccessful check.
- Read-only turns start no automatic validation. In Ask-first mode backend checks are deferred to the agent's approved tools; the validation stage does not bypass those approvals.
- No language server is installed automatically. `verify: off` continues to disable automatic shell checks. Additional checks beyond the automatic budget are listed as missing coverage.
- Task context snapshots live in Lumen's application-data directory, not the project, and are removed when the conversation is deleted.

## Configuration and documentation

- [Task continuity and code quality](../task-quality.md) documents the task ledger, language-server configuration, automatic custom checks, limits and acceptance scope.
- English and Italian READMEs, feature documentation and the roadmap reflect 0.6.0. Historical 0.5.3/0.5.4 notes and previously recorded Godot validation evidence are retained.
- Existing accounts, conversations, native CLI authentication and project configuration remain in use. SQLite adds the task-state table automatically; repository indexes are refreshed for the new cache format.

## Verification

Automated regression coverage includes:

- Task-state persistence/reopen, Compact seeding, Rewind, permissions and decisions beyond the transcript cutoff.
- Workspace changes, root/project association, running-turn refusal and new-project spill-file placement.
- LSP push/pull framing, Unicode, stale versions, read-only callbacks, unavailable servers, timeouts and preservation of partial error evidence.
- Actual failing/passing shell checks, cancellation, nested project selection and checkpoint-based change detection without provider file events.
- Shared-contract changes and deletions, former callers/tests and impact passed into an Orchestra worker's prompt.

Local preflight: 104 Rust tests passed (9 live tests excluded), 59 frontend tests passed, all 23 Chromium end-to-end tests passed with two workers, TypeScript/Vite build passed, Clippy passed for all targets with warnings denied, and formatting/diff checks passed. The release workflow builds Windows and Apple-silicon macOS packages; the main CI workflow also checks Linux. CI results are linked from this release's commit.

## Downloads and scope

- Windows: NSIS installer and portable executable.
- macOS: Apple-silicon DMG.
- SHA-256 checksums accompany the release assets. Linux packaging is not part of this release workflow.
- These are unsigned alpha builds. Clean-machine installation, signing/notarization and native accessibility acceptance remain separate work.
- LSP protocol tests use controlled peers. Interoperability with real installed Rust/TypeScript/C#/Godot servers and live provider turns remains acceptance work; no toolchain components were installed as part of this release.
