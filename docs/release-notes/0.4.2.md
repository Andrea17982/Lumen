# Lumen 0.4.2 — Working state, drafts and Ask-first for Claude

## New

- **Working indicator.** While an agent works, a line with animated dots shows what it is doing under the last answer: *Working*, *Thinking it through* or *Calling a tool*.
- **Reasoning in a disclosure.** Reasoning no longer appears inside the answer. It sits in a chevron disclosure, closed by default. Inline `<think>` blocks from local models are separated the same way.
- **Commit message draft.** A banner above the composer drafts a commit message from your uncommitted changes. **Copy message** copies it. Lumen never runs `git commit`.
- **Handoff draft.** On long conversations, the generated handoff summary is editable. **Continue in a fresh session** uses your revised text, or Lumen's own summary if you leave it empty.
- **Ollama titles.** Chats with a derived title get a short title from the local Ollama model after the first answer. A title you renamed is never touched, and if Ollama is off or unavailable, the default title stays. Settings → Teamwork → Local assistant (Ollama) has the switch and the model choice.
- **Orchestra limits.** Settings → Teamwork sets the maximum number of agents running at once, the total subtasks per run and a quota threshold per provider. Ollama is not listed. When a limit is reached, new subtasks wait with a "Queued" reason and start as soon as a slot frees. Allow 1 more / Allow N more lets a run go past its total cap.
- **Orchestra Resume after a restart.** If Lumen closes during a run, the next start shows the run as **Interrupted** with **Resume** or **Discard**. Completed subtask results and their patches are kept, and attempts already used still count toward the limit of three. Before resuming, Lumen stops any CLI process left from the previous session, after checking its start time so an unrelated process with the same ID is never touched.
- **Approve each action (Claude).** A new permission mode for Claude: every file write or command asks for approval in the chat panel, with approve and reject. The read-only **Ask** mode is unchanged. Codex does not support this mode yet and says so instead of running without approvals.

## Notes

- Orchestra subtasks do not use Approve each action yet.
- Orchestra's new limits and Resume were verified with the test suite and with a fake-process test, not in a full live run on a large project.
- The Claude approval path was tested end to end with a real small Haiku turn: approval reached the broker, the file was written and the turn finished.
- Unsigned alpha builds: Windows may show a publisher warning; on macOS right-click → Open the first time.

## Known limits

- The native window was not checked by hand for the approve/reject buttons, the countdown and the working indicator. Browser tests do not call the backend.
- Codex approvals (`app-server` runner), Orchestra live runs on large projects, clean-machine installs and macOS/Linux behavior are still open. See the roadmap.
