# Lumen 0.15.0

Onboarding and repair. You can sign in to Claude Code and Codex without a terminal, see each account's state in one place, repair Lumen with one button, and receive signed updates.

## Sign-in and accounts

- **Claude Code and Codex sign in without a terminal.** Lumen runs each CLI's official sign-in with no window, and the CLI opens the provider's page in your browser. Codex finishes by itself. For Claude Code, paste the code the page shows into Lumen, which hands it once to the CLI and keeps nothing. **Open the page again** helps if the browser did not open. Lumen counts the account as signed in only when the CLI's own status confirms it.
- **OpenCode, Antigravity, Cursor and Droid** keep the terminal sign-in, because their CLIs need it. While the terminal is open, Lumen checks the account every few seconds and shows it as connected as soon as the CLI reports it. You no longer need to come back and press Check.
- Each account shows its CLI version (or that the CLI is missing), its sign-in, its quota windows with when they reset, and when the quota was last reported. **Sign in again** is in the account's menu, and a new account goes straight to its sign-in.

## Repair Lumen

- **Settings › Maintenance › Repair Lumen** runs these checks:
  - **Service.** If the service does not answer, Lumen restarts it. It asks the service to stop first, and ends it only if it is a Lumen service and still does not answer. The banner shown when the service is unreachable or another version is running now has its own **Repair** button.
  - **Database.** SQLite's integrity check runs, then a backup is saved in `backups` in the data folder. The newest five are kept.
  - **Conversations.** A conversation left looking active with nothing running is closed as interrupted. Its work is kept, never replayed.
  - **Agents.** Each agent's CLI is checked: installed, version, signed in.
  - **Task folders.** Task folders left behind are listed with their unsaved files. Removing one asks first, and its branch stays.

## Signed updates

- Lumen checks GitHub for a newer version at startup and every six hours. It only tells you about it: nothing is downloaded until you choose **Download and install**, in the banner or in Settings › Maintenance.
- Each update is signed. Lumen verifies the signature against the key built into Lumen before installing anything.
- Lumen refuses to update while work is running. Before installing it backs up the database and stops the service.
- **Go back to** reinstalls the version the last update replaced. If that version cannot read your current data, Lumen restores the copy made before the update and keeps the newer one in the backups. It becomes available once you have updated from 0.15.0 to a later version.
- The installed app updates itself. The portable ZIP and the Linux package show the new version and a link to its release page.

## Reliability

- **Stop works from the first second.** Stop now cancels a message while Auto is still choosing the agent, checking sign-ins or reading catalogs. Before, it had no effect and the turn started anyway. The message goes back to the composer, and nothing is recorded.
- **Faster sends with OpenCode configured.** Auto no longer asks the Claude and ChatGPT CLIs whether they are signed in before every message. It remembers each answer for 10 minutes, or one minute when the account was signed out. Check, a sign-in and Repair ask again.
- **No more endless waits.** A command the service never answers now fails after 3 minutes, or 15 minutes for checks, publishing, applying, installs, sign-in and Orchestra. Lumen never repeats an action it cannot confirm: you are asked to review its result.
- **Apply and Discard leave a locked folder intact.** When a program holds the task folder, they now leave the folder and the project exactly as they were. Before, removal could delete part of the task folder before failing, and Apply could then refuse to finish. An automated test now holds the folder open and checks that nothing is copied twice or lost.
