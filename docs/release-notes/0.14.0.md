# Lumen 0.14.0

A stability release. It adds no new features: it fixes how Lumen behaves when something goes wrong, so a conversation never looks stuck and a stop is never mistaken for a failure.

## Autopilot

- When the agent explains why it stopped, the stop is no longer reported as an error. A reported blocker, two attempts without new progress, or the new limit of 10 attempts keep the reply and its work. A note says why Autopilot stopped, and the conversation is marked **Partial**. Errors are kept for real failures of Lumen or the provider.
- Autopilot's instructions now separate the three outcomes. **Done** means the work was delivered, even when a check could not run here; the reply then names what was not verified. **Continue** means the agent can do more on its own. **Blocked** means it needs something only you can provide. Decisions are asked as questions instead of ending the turn.
- Stop always wins: a reply stopped while the agent reports a blocker ends as interrupted.
- After a stop, Lumen starts no automatic repair turns or reviews.

## Service and connection

- A service that exits while starting (for example a damaged database) now says why, instead of leaving the window on "Connecting" forever. The service's error output for its latest start is kept in `service.log` in the data folder.
- A login item blocked by policy or antivirus no longer prevents the service from starting.
- A client that connects and immediately disconnects can no longer stop the service on Windows. Before, this could end every running turn.
- An event that cannot be saved is still delivered, and the window reads the state again, so a finished turn cannot keep looking active.
- If a conversation cannot be loaded, Lumen says so and retries by itself (after 1, 2, 4 and 8 seconds), then offers **Retry**. Before, it could show "Loading…" forever.
- **Quit** in the notification area no longer does nothing when the service cannot stop: the window comes back with the reason. If the service is already gone, or belongs to another version, the window closes.

## Stop and recovery

- Stop ends a conversation that still looks active although nothing runs, for example after a lost final status write.
- A turn that ends abnormally releases its conversation and is marked as an error, instead of blocking every new message.
- Auto checks whether Claude and ChatGPT accounts are signed out before choosing the OpenCode emergency fallback. A failed or unclear check never counts as signed out, and each check waits at most 5 seconds.

## Task worktrees

- If the task folder is in use (an editor, terminal or dev server), Apply and Discard keep the task and its branch and ask you to close those programs, instead of reporting success and leaving an untracked folder behind.
- Apply records that the changes were copied, so trying again after a locked folder never copies them twice.
- A dependency install that times out now also stops the installer it started.

## Interface

- The model picker in the composer has search: type to filter, use the arrow keys to choose.
- An unavailable OpenCode emergency model is flagged in Settings, where you can switch back to Auto.
- The OpenCode "free" and "console credit" labels are translated.
- OpenCode's model catalog loads faster: its three requests now run in parallel.

## Cleanup

- Old benchmark reports, an unused summary script, a broken manual harness and fixtures nothing used are removed. The reports stay available in the `v0.13.0` tag.
- A test that removed its temporary folder too early on Windows, and failed intermittently in CI, now waits for the system to release it.

Windows x64 installers and portable ZIPs require WebView2. macOS is universal. The Linux x64 package targets Debian and Ubuntu. Close active work before upgrading.
