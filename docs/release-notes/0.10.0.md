# Lumen 0.10.0 — Core and local daemon

This milestone separates the desktop interface from local execution. The public 0.9.0 release remains available on GitHub; 0.10.0 is the next local Windows build until separately published.

- `lumen-core` owns storage, accounts, routing, execution, permissions, orchestration and Moli without Tauri/Wry dependencies. The GUI uses authenticated local IPC to a separate `lumen-daemon`.
- Accepted work, questions, approvals and Orchestra workers continue when the GUI closes or crashes. Reopening attaches to the same service rather than opening the database again.
- Durable ordered events and snapshot reconciliation retain partial output and avoid duplicate streamed text. Schema-4 migration, checkpoint sequences and event pruning are transactional.
- Scheduled quota continuations survive service restarts, consume no inference slot while waiting, remain cancellable and are claimed before submission. Uncertain crashed execution requires explicit Resume.
- A per-root OS lock prevents a second service owner. Windows Job Objects and Unix lifetime guards contain owned processes. External desktop programs remain outside that containment.
- Existing opt-in login startup starts the service quietly. Explicit Quit drains and stops the service; update checks refuse live interfaces or active work. The installer and portable ZIP include the service and existing browser/legal resources.

See [service operations and recovery](../local-service.md), [architecture](../architecture.md), [validation](../validation.md) and the [remaining roadmap](../roadmap-1.0.md). Memory/collaboration expansion, autonomous scheduling beyond quota continuation, LAN/VPN control, pairing and a full updater remain later milestones.
