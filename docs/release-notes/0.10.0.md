# Lumen 0.10.0 — Local service, memory and recurring tasks

Release 0.10.0, 17 November 2026. Lumen now runs its work in a local background service, remembers project decisions, repeats tasks on a schedule and reports multi-agent work with facts it observed itself.

## Highlights

- **Work survives the window.** Execution moved into `lumen-daemon`, a local service the interface talks to over authenticated IPC. Closing or crashing the window no longer stops a turn, a native question, an approval or an Orchestra run; reopening attaches to the same service. Stop Lumen and quit is in the tray and in General settings.
- **Project memory.** Any assistant can save a durable fact (a decision, convention or preference). Lumen writes it, dated and with its source chat, under `## Lumen memory` in the project's `LUMEN.md`, which every assistant already reads. Edit or delete it like any note.
- **Global memory, only with your confirmation.** Preferences that apply to all your projects are proposed under the reply ("Remember for all projects?"). Nothing is stored until you click Save; confirmed facts live in `shared/MEMORY.md` and reach every assistant everywhere. Project notes win on conflict.
- **Recurring tasks.** Ask in plain language ("check the dependencies every 30 minutes until 30 August 2027", "every Monday at 9 summarize the TODOs") or type `/every 1d …`, `/every 08:00 …`, `/every lunedì 09:00 …`. The service runs the task in the same conversation, follows local time across daylight-saving changes, and stops at the end date. Scheduled tasks appear above the composer; × stops one.
- **Recipes.** The bookmark under a finished reply saves the request and its result as a shared skill, so any assistant can repeat it later. The reply confirms the saved recipe name.
- **Verifiable handoffs.** Compact now carries goal, constraints, decisions, done and open work, checks, changed files with the Git diff, uncertainties and the next step, and states that the previous assistant's private memory and native session are not carried over.
- **Honest multi-agent results.** Orchestra's reply ends with **Team result by Lumen**: subtasks done out of total, which failed or did not run, whether the independent audit approved, and whether any project check ran. A per-run time limit (120 minutes by default, up to 24 hours) stops new subtasks from starting.
- **No duplicated commands.** Task and approval commands carry persistent receipts adapted from T3 Code's design: a lost reply returns the saved result instead of repeating the action, and uncertain interrupted commands require review. [Credits, sources and MIT notices](../../src-tauri/resources/legal/t3code/ADAPTATIONS.md).

## Reliability

- Durable ordered events and snapshot reconciliation keep partial output without duplicated streamed text. Migrations up to schema 8 are transactional.
- Scheduled quota continuations survive service restarts, wait without using an inference slot and remain cancellable. Uncertain crashed execution requires explicit Resume; ordinary work is never resubmitted silently.
- One service owns each data directory. Windows Job Objects and Unix lifetime guards contain owned processes; a process whose identity cannot be confirmed is never terminated automatically.

## Checks

239 Rust tests (14 opt-in ignored), 76 frontend tests, 44 production-browser tests, Clippy with warnings denied, formatting, documentation and version checks. Native Windows suites with offline CLI fixtures cover the service lifecycle, routing and quota replay, memory/routines/recipes through the real GUI, handoff quality and execution traces. A live check with Claude Sonnet through the official CLI recognized 6/6 schedule and memory requests and 3/3 project-versus-global memory cases. These checks do not measure model quality or certify every account and CLI version.

## Upgrading

Close active work before upgrading: the update refuses to run while the service has live work. The portable ZIP now includes `lumen-daemon.exe`; extract the whole archive. Back up the application data folder before downgrading: older versions do not understand schema 8.

## Known limits

The end date of a recurring task is end of day in UTC. Memory facts come from model replies, so review them like any model output. Remote control (LAN/VPN), automatic choice of collaborative modes beyond Single/Review/Orchestra and recoverable autonomy remain roadmap work. Packages are unsigned; Autopilot is not an OS sandbox.
