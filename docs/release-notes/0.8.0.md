# Lumen 0.8 — Continuity, shared tools and Liquid Glass

Release scope approved by the owner on 13 November 2026: ship the implemented and verified integrations with explicit limitations. Universal cross-provider compatibility remains on the [next roadmap](../roadmap-next.md); it is not claimed as delivered.

## Conversation and execution

- Rewind retires native provider sessions that contain discarded turns. Compact and same-chat account handoffs retain source-linked decisions and check evidence without replaying unchanged material.
- Missing-session and quota recovery preserve observed effects and partial output. They do not automatically replay a task after a provider may already have changed files or external state.
- Auto/Orchestra enforce saved admission/attempt limits and dependency failures. Completed worker results survive interruption; unavailable explicit audits remain visible. Budget, Default, Quality and quota balancing keep their existing contracts.
- Execution diagnostics distinguish actual provider/tool activity, pending input, failure and observed silence. Silence alone does not trigger another copy of an operation.

## Interface

- The logo opens and closes the glass project sidebar, with restrained motion and reduced-motion support. Light/dark themes and the minimal floating composer remain.
- The permission button shows the current mode and explains each option. Opening its menu grants nothing; changes require an explicit selection.
- A short, skippable first-use tour highlights projects, accounts, providers, permissions and execution progress. It can be replayed from Settings or the command menu; it sends no prompt and changes no permissions.
- Keyboard focus, dialogs, historical-message access and native questions received targeted Windows accessibility corrections. Narrator label intelligibility was confirmed by the owner; this is not a general accessibility certification.

## Shared integrations

- Existing local MCP and skill configurations are discovered from provider profiles, Lumen accounts and the active project. Original files, resources, disabled states and account provenance are retained. User and correctly scoped project/local Claude plugin components are recognized.
- MCP elicitation is handled as connector consent, fixing the `Missing or invalid itemId` rejection. Form/URL consent remains explicit, typed and private; stale requests expire on withdrawal, Stop and connection close.
- The owning ChatGPT/Codex gateway exposes configured tools, skills and MCP resources through native RPC without starting a GPT model turn. Authentication remains in its source profile.
- Ollama supports shared stdio and Streamable HTTP MCP, including SSE responses, through its official local model API. Native tool calling and constrained JSON actions both consume actual tool results. It can read scoped skill resources, list/read MCP resources and retrieve prompt templates as data.
- Shared MCP namespaces passed directly to Claude/GPT/Google CLIs require Ask first or Autopilot. Restricted modes expose only the filtered owning-account gateway; Ollama filters its shared tools per tool. Declared destructive tools cannot enter a read-only catalog even if they also advertise a read-only hint. Native provider-local settings retain their own policies; this is not an OS sandbox.
- Tool-list changes refresh the local model's catalog. Expired HTTP sessions do not replay tool calls. Authentication headers are connection-scoped; redirects/proxies cannot forward them elsewhere. Processes and HTTP sessions are closed at turn end.

**Compatibility limits:** this is not universal plugin or connector portability. Claude.ai-only connectors, provider-native hooks/mods/commands/agents, legacy SSE/WebSocket configurations and unsupported native authentication/policy formats still need owning-runtime adapters. Existing cloud connections are not made portable by copying credentials. GitHub/Gmail/Drive OAuth on the reporter's actual account has not been certified. Detected configuration is distinct from a successful remote connection. [Scope and evidence](../shared-capabilities-0.8.md).

## Context and performance

- Targeted TypeScript/JavaScript and Godot import resolution, refresh/deleted-target handoff and comment handling pass the fixed 23-expectation graph corpus. This is not complete language semantics.
- Exact duplicate instructions and repeated unchanged evidence are removed where measured; attachment previews remain bounded without dropping full source references. No universal context-size or token-savings guarantee is made.
- The release retains the 0.7.1 typing, literal-paragraph opening and Windows metadata-shutdown improvements. Historical Windows comparisons measured 63.1% less typing work, 25.6% faster opening and 37.2%/57.4% shorter Claude/Codex metadata calls on their specified workloads. These are scoped historical results, not new 0.8 speed or live TTFT claims.
- Complete transcript history remains mounted. The virtualized prototype failed search/selection/history gates and is excluded. Rust Markdown migration, warm CLI pools and unproven context encodings were not integrated. Repeated warm opening drift remains a documented limitation.

## Validation and distribution

Native Windows tests use isolated data and offline provider/API fixtures; official installed-CLI metadata probes are separate from inference. The development live ledger remains **13 historical slots, no additional inference or login**. Cross-platform CI/build evidence is distinct from native macOS/Linux desktop and real-account acceptance. See the [release-readiness record](../release-readiness-0.8.md) for the exact final checks and publication state.

Distribution: Windows x64 installer and portable ZIP, universal macOS DMG, Linux DEB/AppImage and SHA-256 manifest. Packages remain unsigned. Publication follows the package/checksum gates recorded in the release-readiness record.
