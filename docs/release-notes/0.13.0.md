# Lumen 0.13.0

## Auto, Autopilot and recovery

- Auto rates model capability and reasoning effort separately, recognizes complex research, and chooses an available model and effort from the provider catalog. Budget favors remaining quota, Default favors chat continuity, and Quality favors task specialization when suitable accounts are available.
- Short continuations such as “prosegui” inherit the previous task rating. Task worktrees stay associated with their original project, keeping conversations visible in the sidebar. Lumen can release the worktree once its changes are safely integrated.
- Explicit or consequential Codex questions appear as interactive choices. Autopilot waits for the answer and resumes the native turn. Inline completion markers are removed from the displayed reply.

## Verification and handoff

- Lumen reuses compact check evidence for corrections, independent review, and handoffs between accounts. Review sees the latest results for the current diff. The captured log is available in the expandable verification step, subject to capture limits.
- Full handoff prompts put stable instructions before changing context. This prepares the prefix for reuse. Its independent effect on cache hits has yet to be measured.
- Shared session-state logic, provider identifiers, fixtures, and build documentation reduce duplication.

## Codex benchmark

Two paired synthetic Python tasks ran on a real Codex subscription with GPT‑6.2 Sol at low effort. The harness applied Codex's proposed edits and independently verified them. These figures cover the correction turns.

| Metric | Before | After |
| --- | ---: | ---: |
| Total input tokens | 47,939 | 39,625 (−17.3%) |
| Input tokens outside cache | 9,795 | 1,993 (−79.7%) |
| Cached input tokens | 38,144 | 37,632 |
| Share of input served from cache | 79.6% | 95.0% |
| Output tokens | 104 | 102 |
| Acceptance checks passed | 11/11 | 11/11 |

Both tasks passed in both arms. The higher cache share came with a smaller input and slightly fewer cached tokens. The sample measures these correction turns. It provides no estimate of subscription-wide savings or quality on larger tasks.
