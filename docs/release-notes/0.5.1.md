# Lumen 0.5.1 — Native sessions, smarter Auto and the code graph

This release is about answer quality. With the same model, account and effort, Lumen answered worse than the native Claude Code and Codex apps. The causes were in how Lumen called the CLIs, and they are fixed here.

## Better answers

- **Native CLI sessions.** Each turn used to start a new CLI session and replay the chat as flat text, which lost tool calls, files already read and the prompt cache. Lumen now continues the CLI's own session (Claude `--resume`, Codex `exec resume`) and sends only the new message. If a session can no longer be resumed, the turn is retried once with the full history. Self-healing and the revision after a cross-audit continue the same session too.
- **The model can check its work.** In File edits and Read-only modes, Claude now has planning (TodoWrite), subagents (Task) and allow-listed commands. Read-only gets read-only git commands; File edits also gets build, test and lint (`cargo test`, `npm run build`, `pytest`…). Any other command is still refused.
- **Your instructions and skills apply.** Global `CLAUDE.md` / `AGENTS.md`, skills, agents and commands are copied into each account's isolated folder, along with the shared skills you enabled in Lumen. Credentials and settings stay separate.
- **Long chats keep their goal.** When history is truncated, the chat's first request is kept.

## Auto routing

- **Rated by a small model.** Auto no longer picks the model from keywords in the last message. Haiku at low effort, or the local assistant's Ollama model when you enable it, rates the request together with the previous exchange. A "procedi" after a hard bug stays on a strong model. Keywords remain the fallback.
- **Follow-ups skip the rating.** A short one-line follow-up reuses the previous request's rating, so most turns don't wait for it. A new request waits a few seconds for Haiku.
- **Same assistant through a chat.** Auto stays on the account that answered last, so the native session continues. It switches only if that account is cooling down after a rate limit.
- **Orchestra only for work worth splitting.** Orchestra takes over only when the rating says the work splits into independent parts. A single bug is never split, however hard.
- Removed the unused "parallel perspectives" strategy.

## Code graph

Settings → Teamwork → **Code graph** (on by default) replaces "Repository map references". Lumen no longer adds guessed declarations to the prompt. Claude and Codex get a read-only MCP server with six tools:

- `overview`: the main areas of the project and its most depended-on files.
- `find_symbol`: definitions with exact line ranges and signatures.
- `symbol`: what a definition uses, and every place that uses it, grouped by the calling function.
- `file_outline`: a file's structure without reading it.
- `related_files`: imports, shared symbols and files that git shows changing together.
- `impact`: what a change can break, and which tests to run.

The index covers Rust, TypeScript/JavaScript, Python, Go, C#, Java, Kotlin, C/C++, PHP, Ruby, Swift, GDScript, SQL and Godot scenes. It refreshes only changed files. On Lumen's own repository it builds in about 0.3 s and answers in milliseconds.

## Fixes

- Orchestra limits: moving from one limit field to the next could lose the second edit while the first was saving.
- CI: Linux build dependencies added; the macOS job no longer stops when the Linux job fails.

## Notes

- Verified live with real accounts: Claude and Codex resume their sessions and call the code-graph tools, and Claude runs the allowed git commands.
- The code graph finds definitions with per-language patterns, not a full parser. Rust and TypeScript are the most precise.
- Not yet covered: the code graph in Ask-first mode, and Gemini or Antigravity sessions.
- Unsigned alpha builds: Windows may show a publisher warning; on macOS right-click → Open the first time.
