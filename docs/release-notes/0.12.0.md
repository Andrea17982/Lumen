# Lumen 0.12.0 — Experimental Code Mode and turn-local context

Release 0.12.0, 21 November 2026. Agents can now write a short JavaScript program that calls Lumen's tools, instead of one tool call per model round-trip. The program can also read large inputs piece by piece and ask a submodel focused questions. Everything is **off by default** and opt-in, because the measurements so far do not justify turning it on for anyone.

## Experimental Code Mode

- **One script, many tool calls.** With `"codeMode": "on"` in the daemon's `settings.json`, official API turns and Claude Code, Codex and OpenCode get a `lumen_code` tool. A script can queue up to 200 host calls with eight in flight, within 120 seconds and a 256 MiB JavaScript heap. Its variables last for the turn. `off` is the default; `auto` keeps classic calls until model validation is done.
- **Same permissions as classic calls.** Every call inside a script follows Lumen's normal permission and approval path, keeps the same audit log and trust classification, and actions that can prompt or change shared state run in order. A denied call is returned to the script as a readable error.
- **Local Ollama, per model.** Add a model's exact ID to `"ollamaCodeModels"` to enable it. Models with native tools get `lumen_code`; the others use `action: "code"` in the structured envelope. After two consecutive JavaScript syntax errors Lumen records a fallback and continues the same turn with classic calls.
- **Native CLIs.** Claude Code, Codex and OpenCode reach Code Mode through `lumen-daemon --lumen-code-mcp`, which relays to the active turn over an authenticated loopback channel. Scripts see the turn's workspace, Moli, graph, shared MCP servers and skills. Cancelling the MCP request interrupts the script. Cursor is not included.
- **Large output.** Output over 24 KiB shows a head/tail preview, with **Show full output** in activity.

## Turn-local context and subqueries (RLM)

- **`context`.** Scripts can list, read, slice, search and chunk up to 32 MiB of selected attachments, transcript, handoffs and large tool output, without putting it all in the prompt.
- **`llm(prompt, {effort, maxTokens})`.** Sends an explicit prompt to a text-only submodel with no tools. The router prefers an installed local model, otherwise an API account opted into Auto, and each API request reserves budget through the same ledger as the main turn. An Ollama turn stays on its selected model.
- **Limits by effort.** `low` allows no subqueries, `medium` 8, `high` 32 and `max` 128 per turn, with nesting up to depth 2 only at `max`. The parent turn's effort is the ceiling. [Configuration and limits](../api-access.md#experimental-code-mode).

## In the conversation

- Each script appears as a collapsed **Code** row with the script and its child calls; long scripts load in full on request. Billable subqueries are added to the existing API estimate.
- The execution trace records content-free Code Mode counters: script time, host calls, submodel requests, bytes shown and withheld, and whether the turn fell back to classic calls.

## Measurements

All benchmark runs used local or scripted models and spent USD 0 on inference. No configuration met the bar for making Code Mode a default.

- **Qwen3-Coder 30B (Ollama), five paired seeds:** classic tools → Code Mode went from 0/5 to 5/5 on repeated file edits, but from 5/5 to 0/5 on log filtering. Explicit MCP text instructions did not fix the log-filter case.
- **Long context:** classic tools, Code Mode and Code Mode with RLM scored 5/20, 4/20 and 5/20. The model made no `llm()` calls on its own.
- **Other local models** (gpt-oss 20B, Qwen2.5-Coder 7B, Llama 3.2 3B) lost quality or saved nothing. [Full results](../../reports/bench/2026-11-18/summary.md).

Paid API models, CLI subscriptions and the packaged desktop app have **not** been measured with Code Mode yet.

## Interface fixes

- Escape now closes the Usage popover; before, it closed the sidebar and left an invisible layer blocking every click.
- On mobile, the Settings panel no longer sits under the floating Lumen button.
- The "Move to" project picker in the conversation menu keeps its arrow on the same line.
- Markdown tables no longer split words in narrow windows; they scroll sideways.
- Settings tabs stay on one scrollable row in Advanced mode, with fades on the edges that still have hidden tabs.
- The Lumen mark is darker in light theme and now passes 3:1 contrast.
- Every button now shows where keyboard focus is.

## Documentation

- New Code Mode sections in [API access](../api-access.md) and [Moli](../moli.md).

## Checks

293 Rust tests (17 opt-in ignored), 81 frontend tests, 52 production-browser tests, Clippy with warnings denied, formatting, documentation and version checks; CI on Windows, macOS and Linux. Code Mode is covered by unit, fixture and browser tests, including permission denial inside scripts, MCP cancellation, syntax fallback and RLM routing. A browser sweep of 228 interface states across desktop, tablet and mobile in light and dark found no layout defects or console errors after the fixes. Code Mode has not been driven through the packaged desktop app, and no paid model was measured.

## Upgrading

Nothing changes unless you opt in. Close active work before upgrading: the update refuses to run while the service has live work. The portable ZIP still needs `lumen-daemon.exe` beside `Lumen.exe`; extract the whole archive.
