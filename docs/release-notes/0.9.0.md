# 0.9.0 — Official access and adapter compatibility

Release 0.9.0, 16 November 2026. Completes the compatibility milestone. GitHub distribution packages use portable CPU targets and pass the release workflow; local `builds/latest` packages are separately verified CPU-native Windows builds.

- **Official OpenAI, Anthropic and Google APIs:** independent account slots with OS-keychain keys, fixed HTTPS origins, exact priced model selection and common Moli/graph/MCP/host tools. All four access profiles, cancellation, usage and per-reply cost estimates are integrated. Auto requires explicit opt-in and a positive cumulative model budget. Durable reservations precede each request, survive crashes/uncertainty and serialize concurrent spend. Model/rate changes require price confirmation; output-limit changes invalidate a prepared request. [Configuration and budget boundaries](../api-access.md).
- **OpenCode 2.2.7:** replaces the initial print-only runner with official ACP and native session-policy API. Policies are read back before prompting. Only the active owned session can publish events or request permission; premature/foreign callbacks are denied. Read only/File edits deny shell, outside-project writes, Code Mode and custom subagents; Ask uses one-shot decisions. Native continuation preserves session/workspace identity and ignores replayed history; selected models are confirmed, including project-configured models. Moli, graph and supported shared MCP are bridged. The old print normalizer/fixture is retired.
- **Compatibility contract:** nine adapters and explicit capability/permission/event/error/usage/cost/fallback declarations in Settings. Unknown events are retained conservatively. No invented token, cost, model or entitlement data. [Matrix and audit](../integrations.md).
- **Continuity:** retains the earlier fixes for “Prosegui.” task/model-class inheritance, weaker-model consent, partial output and one opt-in native resumption after quota. Stop expires pending decisions and kills owned process trees; no observed tool work is automatically replayed.
- **UI/documentation:** API setup uses the existing account settings, clears saved password input and reconfirms changed pricing. The nine-provider bar stays on one line with local scrolling when needed. The owner-approved satin-glass Lm brand remains. One canonical 1.0 roadmap replaces superseded roadmaps; legal resources include verified notices for the new keychain/TLS dependencies.

## Declared boundaries

Cursor remains explicit Autopilot only; OpenCode/Cursor keep one existing native profile and are not automatic destinations or Orchestra workers. API responses are buffered, text-oriented, with no native session/image/skill/hook/subagent runtime or arbitrary reasoning controls; budgeted API collaboration remains in the collaboration milestone. OpenCode ACP input-token/cost reports are unavailable rather than estimated as provider reports. Proprietary cloud/runtime portability, legacy SSE/WebSocket, owner-bound OAuth/helper translation and broader restricted-client tool filters remain explicitly limited in the compatibility audit. No credentials or extension files are copied to claim parity.

No paid API inference, naturally exhausted real-account reset or new macOS/Linux desktop acceptance was run. CI packaging/helper probes are separate from interactive desktop acceptance. Prices are user-confirmed estimates, not invoices; external tool fees are separate. Autopilot is not an OS sandbox. Local Windows artifacts use the build CPU’s instruction set and are unsigned; CI baseline builds remain separate.

Close active work before upgrading. Back up the application data before downgrading: older versions do not understand the new API provider identities. Do not point an older build at active 0.9 data and assume safe resume. Removing an API slot deletes its keychain credential; historical budget records remain local.
