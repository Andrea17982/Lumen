# Lumen 0.11.0 — Auto as a team, plugins and recoverable autonomy

Release 0.11.0, 18 November 2026. Auto now decides how your agents work together, competes for the best solution when you ask for quality, answers agents' questions for you, and can be extended with plugins that declare their permissions.

## Auto

- **Collaborative mode.** After planning, Auto picks Parallel or Collaborative with a deterministic rule. When every step depends on the previous ones, or two steps write the same file, agents take turns on one chain and each turn sees all earlier patches and results.
- **Compete (Quality profile only).** For important or uncertain changes, two providers write independent solutions in isolated worktrees. Lumen runs the project's checks on each, a reviewer from a different provider compares the passing ones, and only the winner is applied. Default and Budget never compete, because Compete uses about twice the quota. On an offline corpus of six tasks with tests, Compete solved 5 and Single 3; this is an internal fixture measure, not a comparison with other products.
- **No questions to you.** In Auto, agents' clarifying questions get a deterministic answer (the recommended or first safe option, or "proceed with a reasonable assumption"), listed under **Assumptions Lumen made** in the reply. Permissions, secrets, browser and connector actions, and anything risky or external still come to you. Other modes are unchanged.
- **Team result by Lumen** now states the mode used, which Compete candidate won and why, and any fallback.

## Plugins

A plugin is a folder with `lumen-plugin.json`. It can add themes (CSS tokens only), slash commands, shared skills, MCP tool servers and panels. Every plugin declares what it needs (project files, network hosts, shell, secrets: none by default); you review this before installing, plugins stay off until you enable them, and an update shows any added permission. Panels run in a sandboxed iframe with no access to Lumen's IPC, and MCP servers start with a scrubbed environment. Install from a folder or an HTTPS Git URL in **Settings → Plugins**; three examples are in `plugins/examples/`. [Plugin guide](../plugins.md).

## Recoverable autonomy

- Commands and tools are classified as reversible, risky or external, with an audit log per conversation. Lumen's own tool loops confirm irreversible commands even in Autopilot.
- Rewind refuses to run when another conversation shares the checkout or when a discarded native turn touched files outside it (adapted from T3 Code's restore safety, [credits](../../src-tauri/resources/legal/t3code/ADAPTATIONS.md)). A snapshot is taken before every restore, so a restore can itself be undone.
- Snapshots and restores are byte-exact for line endings and Git filters.
- Project memory and routines proposed after reading untrusted content (web pages, tool output) wait for your confirmation instead of being saved automatically.
- Rollback limits for databases, remote services and files outside the project are in [Autonomy](../autonomy.md).

## Collaboration details

- **Worker approval inbox.** Approval requests from Orchestra workers show the agent and subtask. Parallel workers of one chat no longer replace each other's requests, and a request from a stopped worker stays visible as expired.
- **Handoff corpus.** An offline corpus checks that constraints and decisions survive two compactions and reach Claude Code, Codex, Antigravity, OpenCode and the three API adapters in each one's real format.

## Long conversations

Large tool output reaches the interface shortened, with its full size shown, and loads in full on request. The complete output stays in the backend. Finished messages are no longer re-rendered while a new one streams; in a 2,000-message transcript streaming stays at 60 fps on the test machine.

## Checks

273 Rust tests (14 opt-in ignored), 81 frontend tests, 50 production-browser tests, Clippy with warnings denied, formatting, documentation and version checks; CI on Windows, macOS and Linux. New features are covered by unit, fixture and browser tests. They have not been driven through the real desktop GUI with the native Windows harness, and no live model run was made for this release.

## Upgrading

Close active work before upgrading: the update refuses to run while the service has live work. The portable ZIP still needs `lumen-daemon.exe` beside `Lumen.exe`; extract the whole archive.

## Known limits

Compete needs two different providers with quota available, otherwise Auto falls back to Single or Review and says so. Plugin panels and Git install have not been tried in the packaged app. A plugin's MCP server is a normal program: Lumen controls what it is given, but does not put it in an OS sandbox, so install MCP plugins only from authors you trust. Packages are unsigned; Autopilot is not an OS sandbox. [Validation](../validation.md).
