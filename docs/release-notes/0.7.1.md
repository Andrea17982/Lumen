# Lumen 0.7.1 — Performance Update

This patch ships the completed performance and reliability checkpoints developed for the 0.8 roadmap. The remaining roadmap stays open; this is not a declaration that every 0.8 experiment is finished.

## Performance

- Long-chat draft typing avoids rebuilding the historical transcript. In the scoped Windows release test with 5,000 mixed messages, median renderer work for a 12-key batch falls from 734 to 271 ms (63.1%).
- A conservative literal-paragraph renderer speeds initial chat opening while retaining the original Markdown/GFM path for syntax and ambiguous text. The final matched Windows release comparison with 5,000 mixed messages falls from 1,406 to 1,046 ms (25.6%). Complete history remains mounted; the windowed prototype failed historical content-access gates and is excluded from normal builds.
- Windows metadata CLI shutdown uses a supervised Job Object, bounded graceful EOF and whole-group cleanup. The fixed installed-CLI A/B/A/B comparison reduces complete metadata-call medians by 37.2% for Claude and 57.4% for Codex, including supervision overhead. Median shutdown falls from 428/423 to 44/18 ms. Cancellation, task abort and descendants surviving their parent are covered by controlled process tests. Model-turn and non-Windows shutdown policies retain their existing behavior.
- Content-free monotonic timing offsets distinguish command preparation, CLI startup, protocol initialization, request enqueue/acknowledgment where available, first normalized text and return. Timing signals use existing snapshot persistence.

These are local, scoped measurements with synthetic/offline workloads or metadata-only CLI calls. They are not cold-start guarantees, real model TTFT, general memory savings or official-app performance parity. [Methods and excluded candidates](../performance-0.8.md), [opening](../initial-open-0.8.md), [turn attribution](../turn-latency-0.8.md), [metadata shutdown](../metadata-shutdown-0.8.md).

## Reliability and execution

- Draft text and attachments remain with their conversation. Immediate pending delivery frees the composer; delayed acceptance, rejected requests and uncertain readback recover without automatic duplicate submission or overwriting another draft. Draft persistence remains window-local.
- Compact execution progress distinguishes provider return, questions/permissions, tool lifecycle, failure, interruption and observed silence. A quiet provider is not automatically restarted, and a normal provider return is not presented as proof that the task is complete.
- Same-chat account handoffs and native continuation receive changed owned notes/check evidence without repeating unchanged context. Auto quota precedence and bounded follow-up routing are corrected; independent audits remain proportional and explicit requested audits cannot silently disappear. Manual provider/model choices and Both retain their contracts.

The prior bounded GPT coding experiment supports targeted check-evidence corrections; it does not establish universal model-quality parity. Claude live authentication/actual multi-account topology, broader Auto delegation and platform/screen-reader acceptance remain distinct open limits. [Quality evidence](../quality-experiments-0.8.md), [validation](../validation.md).

## Distribution and remaining scope

Windows x64 installer and portable ZIP, universal macOS DMG, Linux DEB/AppImage and a SHA-256 manifest follow the existing release workflow. Windows package helpers are checked on a clean runner; macOS/Linux automated build/test evidence remains separate from native desktop testing. Packages remain unsigned.

No additional model inference was used for the performance tranches; the prior live experiment ledger remains 13 spent slots. Full compatible virtualization, provider inference/TTFT measurements, warm process pools, the approved future logo/sidebar composition and remaining graph/desktop acceptance stay on the [0.8 roadmap](../roadmap-0.8.md).
