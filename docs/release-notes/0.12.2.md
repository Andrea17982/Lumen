# Lumen 0.12.2 — Automatic Code Mode, a simpler app and faster releases

Release 0.12.2, 23 November 2026. Code Mode is now **on by default** in an automatic form. It costs nothing on short turns and saves tokens and round-trips on turns with many tool calls. Several rarely used features are gone, which makes the interface simpler. Godot support moves to a separate plugin.

## Automatic Code Mode

- **Classic calls first, scripts when they pay off.** API and Ollama turns start with ordinary tool calls. After five rounds of tool calls, or when a tool result is larger than 24 KiB, the rest of the turn uses `lumen_code`. The large result is kept as a context document that the script reads with `context.get(id)`.
- **The model is told what changed.** When the turn switches, the model gets the reason, an example script that uses the tool it just called, and the sandbox rules (no `fs`, `require` or `process`).
- **Measured.** Local gpt-oss 20B, 50 paired runs: successes went from 45 to 50, with no task lost. On many-call edits it used 45% fewer tokens and 42% fewer round-trips. On the other suites it behaved exactly like classic calls. [Results](../../reports/bench/2026-11-23/summary.md)
- **Where it applies.** On Ollama, Automatic covers only model families that keep their quality in Code Mode (currently gpt-oss); Qwen3-Coder stays on classic calls. Claude Code, Codex and OpenCode keep their direct tools unless you choose **Always**.
- **New setting.** Code Mode is now in **Settings → Teamwork → Code Mode** (Advanced): Automatic, Always or Off.

## Removed

- **Both mode** and its manual merge and version previews. In Auto with the Quality profile, **Compete** covers the same case: it runs your project's checks and has a reviewer choose.
- **Layout canvas** and the **screenshot library** in the project inspector. The global capture shortcut still attaches a screenshot to your next message.
- **Ollama helper** for titles, commit-message drafts and handoff drafts. **Long conversation** now continues in a fresh session with the built-in summary. Ollama as a conversation provider is unchanged.
- **Built-in Godot controls.** They are replaced by the plugin below.

## Godot plugin

`plugins/godot` is a standalone plugin. You install it from **Settings → Plugins**. It finds the Godot projects in the conversation folder and the Godot editor, and it opens the editor on a project. A skill tells agents how to run, stop, reload and capture scenes through your project's own Godot MCP server, and the `/godot-play` and `/godot-editor` commands start those tasks. [Plugin](../../plugins/godot/README.md)

## Releases and development

- Release builds no longer repeat the tests CI already ran, and they publish directly once every package passes its smoke test.
- Manual, measurement and live harnesses moved to `tests/manual`.

## Checks

- Automated: 293 Rust tests (17 opt-in ignored), 63 frontend tests, 51 production-browser tests, Clippy with warnings denied, formatting, and documentation and version checks.
- CI on Windows, macOS and Linux.

## Upgrading

If your settings file says `"codeMode": "off"` because that was the old default, it now reads as Automatic. To keep Code Mode off, choose **Off** in Settings. Settings for the removed Ollama helper are ignored. Close active work before upgrading. The portable ZIP still needs `lumen-daemon.exe` beside `Lumen.exe`.
