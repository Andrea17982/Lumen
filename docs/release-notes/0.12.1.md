# Lumen 0.12.1 — Code Mode measured on every provider, recoverable autonomy

Release 0.12.1, 22 November 2026. Code Mode was measured on local models and on Claude Code and Codex through their subscriptions. It now works the way Anthropic's Code Mode does: when it is on, Moli and MCP tools are reachable only from a script. Autonomy is easier to recover: restores are faster on large repositories, budgets and time limits hold across restarts, and the native API suite runs again. Code Mode stays **opt-in**.

## Code Mode

- **Tools only through code.** With `"codeMode": "on"`, Claude Code, Codex and OpenCode no longer receive Moli and the shared or project MCP servers as direct tools. They reach them only from `lumen_code`, with the same permissions and approvals. The servers Claude Code would load from the project's `.mcp.json` are denied as direct tools too. The CLI keeps its own shell and file tools. Before this change, neither CLI ever chose `lumen_code` when direct tools were also offered.
- **When it helps.** It pays off with large tool results. Reading twelve 30 KB files to count one value cost Claude Code about 357k uncached tokens with direct tools and 37k from a script (−90%), and it answered correctly more often (1/3 → 2/3). With small results a script adds a few model requests. Codex already makes parallel calls and shortens long MCP results, so it saved nothing.
- **Easier scripts.**
  - Tool results expose `r.text`, and `console.log` works.
  - Errors quote the failing script line with a hint, and an unknown tool name suggests the closest one.
  - Catalogues over 40 tools list names only, plus the name of each MCP server. `searchTools` and `describeTool` find the rest without a host call.
  - `context.grep` accepts a RegExp.
- **Direct calls are routed.** When a model calls a listed tool directly instead of `lumen_code`, Lumen runs it as a one-line script with the same dispatch and permissions. This was the main reason gpt-oss failed in Code Mode.
- **Ollama context window.** Lumen now sizes `num_ctx` to the request, from 8K up to the model's limit. Before, Ollama's 4K default silently dropped the start of long prompts, tool lists included.
- **Subqueries.** When subqueries are allowed, the `lumen_code` description now states the turn's `llm()` limits and shows the batch-and-combine pattern.

## Recoverable autonomy

- **Faster Rewind on large repositories.** Restore now touches only the paths that differ from the checkpoint. On 50,000 files with 2,500 changes it went from 66 s to 11 s and stayed byte-exact.
- **Time limits survive Resume.** An Orchestra run keeps the active time it has used. A restart followed by Resume no longer grants a fresh two hours, and downtime does not count.
- **Budget exhausted mid-turn.** A work step the model already finished stays done. Nothing more is sent, and the error says why. This is covered by a native fixture.
- **Permission matrix.** A test runs read, write, command, destructive command and `git push` under every access profile, through classic calls and through Code Mode, and checks for missing and extra prompts.
- **Service stability.** Service workers now have an 8 MiB stack. A debug build overflowed tokio's 2 MiB default on the first API tool turn.
- **Hardening.** Broker capabilities are compared in constant time.

## Measurements

- **Local models (Ollama, five seeds, suites A–F).** No model met the bar for making Code Mode a default.
  - gpt-oss 20B (low) kept its quality (44/50 → 46/50) but used more tokens overall. It saved 58% of round-trips on many-call edits and 84% of tokens on an 88-tool catalogue.
  - Qwen3-Coder 30B lost quality.
- **Subscription CLIs (Codex `gpt-6.2-sol`, Claude Haiku, three seeds).** See *When it helps* above. Quality: Codex 18/18 in both arms; Claude 16/18 → 17/18.
- **Not measured.** Paid API keys.

## Developer tools

- `tests/live-code-mode.mjs` is an opt-in runner (`LUMEN_LIVE_CODE_MODE=1`). It compares Code Mode off and on through the subscription CLIs and reads token totals from the CLIs' own logs.
- `gitops::tests::rewind_scale_probe` measures checkpoint, preview and restore on a large repository.
- The T2 API benchmark runs only with a hard dollar cap.

## Checks

- Automated: 299 Rust tests (19 opt-in ignored), 81 frontend tests, 52 production-browser tests, Clippy with warnings denied, formatting, documentation and version checks.
- CI on Windows, macOS and Linux.
- Native Windows suites for API turns and for service crash and restart.
- Code Mode was driven through a packaged WebView2 build and about 150 live CLI sessions.

## Upgrading

Nothing changes unless Code Mode is on. If it is, Claude Code, Codex and OpenCode see Moli and your MCP servers only through `lumen_code`. Close active work before upgrading. The portable ZIP still needs `lumen-daemon.exe` beside `Lumen.exe`.
