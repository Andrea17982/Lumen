# 0.8.1 — native compatibility and quota continuation

Historical local Windows checkpoint toward 0.9. Current functionality and resolved limits are recorded in [0.9.0](0.9.0.md); this page preserves the earlier checkpoint and is not a remote publication.

- **Continuation quality:** `Prosegui.` and the existing continuation commands inherit the preceding task's model class and reasoning. Manual model choices are now recorded too; legacy manual replies can supply the model-class floor. A chain containing an older incorrectly downgraded continuation can recover the original floor. An unrelated new task remains a boundary. If only a weaker model is available, Auto asks before inference.
- **Quota recovery:** quota errors preserve a valid native session even after partial work. The latest eligible reply offers one opt-in resume at the estimated reset, with the same account, catalog model and permissions. Waiting uses no inference/work slot and is cancellable. Lumen must remain running, including in the tray. Restart requires an explicit new schedule or manual continuation. Changed workspace/permissions cancel the schedule; a lost native session stops without full replay. Unknown reset times use a 15-minute estimate; exhausted reported windows use their latest reset. A second quota error does not create an endless retry loop.
- **OpenCode v2:** explicit provider selection, catalog discovery, native session continuation, streamed text/tool summaries/input-token reports, and cancellation of the owned private-server tree. Uses one existing native OpenCode profile; Lumen does not copy its credentials. **Autopilot only**: Read only, File edits and Ask first are rejected before inference. Lumen-provided MCP/Moli/graph tools, isolated identities, automatic selection/fallback and monetary accounting are not integrated in this increment. Native OpenCode policies still apply; a catalog entry does not establish entitlement. [Official CLI contract](https://opencode.ai/docs/cli/commands), [native permissions](https://opencode.ai/docs/permissions).
- **Cursor CLI (16 November checkpoint):** a first explicit-selection adapter for the official headless CLI. Uses one existing native profile and Autopilot only; restricted profiles fail before inference. Catalog discovery, long stdin, native resume, tool summaries, quota continuation, cancellation and terminal success/error handling are integrated. Cursor stays outside automatic routing/fallback and Orchestra, and Lumen shared tools, isolated identities, input-token reporting and monetary accounting are not integrated. Empty catalog output is an actionable error, never a guessed model list.
- **Typed runtime failures:** schema 1 records quota, cancellation, unavailable adapter/model, permission, authentication and other failures, with retry timestamps for quota errors. Existing UI activity remains compatible; this is not a full typed event/permission/cost protocol yet.
- **Task delivery:** the shared Autopilot instruction explicitly preserves unrelated existing edits and requires requested implementation/build/check work, rather than treating a dirty checkout as a reason to refuse. Model task compliance is still distinct from a returned response.
- **Packaging:** unchanged pinned browser resources are preserved when the previous portable browser is still in use.

## Evidence and scope

Deterministic native fixtures cover flagship continuation after a quota error, consent before downgrade, scheduled native resumption without a repeated file effect, missing-session no-replay, cancellation of a schedule, and OpenCode discovery/resume/permission/cancellation paths. Installed OpenCode 2.2.7 returned a 351-model catalog through Lumen. Its real stdin/NDJSON stream and native session ID were exercised with local Ollama; the small local model did not obey the response/no-tools constraints, so this is transport evidence, **not** a model-quality pass. No new paid remote inference or naturally exhausted real-account reset is claimed. Local records are under `.codex/verification/081-*`.

The remaining 0.9 work includes restricted OpenCode/Cursor permissions/shared tools, official keychain-backed API access and monetary accounting, broader event/capability dimensions, and the remaining integration adapters. Other platforms and all Windows scaling factors were not certified in this checkpoint.
