# 0.8 execution quality, continuity and Auto experiments

Status: local candidate integrated and bounded live experiment concluded, 11 November 2026. Working tree based on `657c679`, preserving the prior composer/observability tranches. No release or version change.

## Fixed protocol before candidates

The scope is coding in React/TypeScript and a tiny standalone Godot .NET 2D project with C# and GDScript. No Rodent Heroes source, assets, services or addons are copied. Native direct sessions remain the default; Orchestra remains explicit. No global shared conversation memory is added.

1. Reproduce routing/continuity defects with deterministic regressions before implementation. Preserve the owning source baseline and hashes under ignored `.impeccable/experiments/quality-baseline/`.
2. Calibrate Auto on a fixed Italian/English corpus: independent new requests must not inherit unrelated prior complexity; difficult single tasks are distinct from parallel deliverables; optional cross-audit must not run on every ordinary coding task in Quality; explicit independent review and costly-risk review remain possible in Budget. Manual account/model/effort/permissions/folder choices must remain unchanged.
3. Test account handoff and return across two isolated Claude fixture accounts and one Codex fixture account. Required facts, corrections and authorization stay in the chat; native IDs never cross accounts; unrelated chats and project roots stay isolated. Validation evidence must remain separate from model prose.
4. Use independent compile/runtime checks for task quality. A promise, self-reported pass, audit approval or process return is not a passing task. Count failures, corrective turns, unrelated changes, full observed token/cost usage and end-to-end elapsed time.

### Acceptance gates

- **Local primary metric:** all required routing and continuity regressions pass, with no manual-choice or permission regression. Corpus results describe rule calibration, not model intelligence. Record baseline and candidate decisions, including errors, rather than reporting only a final pass.
- **Audit protocol:** only a standalone unambiguous approval sentinel accepts an audit. A qualified approval must not bypass corrections. Reviewers remain read-only; inability to obtain an independent review must be reported rather than silently called a pass.
- **Live primary metric:** independently satisfied task requirements on identical fresh task projects. Three paired A/B runs per task and available affected provider; alternate A/B and B/A. A candidate must preserve all hard requirements and show an actual correctness or cost benefit to support a superiority claim. A tie or noisy small sample is inconclusive. Do not choose a winning metric after seeing results.
- **Secondary live metrics:** total wall time, provider-reported input/output/cache and monetary usage where available, additional turns, repairs and unrelated file changes. Missing usage is unavailable, never zero. Include classifier/reviewer/repair calls when those paths are exercised. Local process memory is not the provider's inference memory.
- **Budget:** local evidence first; live calls only for a promising candidate. At most six full task runs (three pairs) per task/provider, including failed attempts; a task may include multiple turns/tools. No automatic budget increase, quota retries, model download or provider substitution. A quota/login/version/prerequisite failure is recorded explicitly. Configured metadata currently shows one Claude and one GPT account; the two-Claude topology can be proven locally, not fabricated live.

The actual cause of earlier live interruptions remains unestablished until reproduced. These experiments do not authorize publishing, changing original projects, or claiming provider parity from fixture results.

## Baseline findings to reproduce

- Any short one-line Auto request can inherit an old verdict, including a new unrelated objective; `previous` can skip a newer unrated manual request.
- `stick_to_previous` runs after usage balancing and can undo the selected account.
- Audit acceptance checks `starts_with("APPROVED")`, accepting qualified or contradictory first lines.
- Quality currently audits every coding-tier Auto task when another provider exists; fallback complexity also treats a hard single task as automatically parallelizable.

Results and decisions are appended after measurements. No claimed gain is established by this initial protocol.

A sixth regression reproduced missing Lumen-added validation evidence on native resume before the context correction. The corpus measures explicit rule expectations, not model intelligence or universal routing accuracy.

Changed evidence is sent once on native resume, bounded to eight recent labels plus clipped details/diagnostics. Full account handoffs include the evidence; native IDs remain account-scoped. Empty/removed context is invalidated explicitly.

The Windows debug offline harness exercises real IPC/SQLite with two Claude fixture accounts and GPT: changed evidence once, unchanged omission, account switches, another-chat isolation, fresh quota precedence and bounded same-provider audit. Unit coverage also checks latest pass replacing failure, project/chat isolation, note changes/removal and recent-label selection. These are controlled execution/prompt tests, not paid model-quality evidence.

The tiny React and Godot projects compile before correction, fail their intended behavior checks, and pass independent compile/runtime checks after reference corrections. ## Live execution notes

The no-inference preflight reported native authentication/catalog availability for Claude Sonnet and GPT 6.1 Terra at low effort. The first actual Claude attempt instead returned an expired OAuth/401 error. It consumes one React/Claude slot; subsequent Claude attempts were stopped, without login retries or provider substitution. No two-Claude live topology is available.

The first React/GPT pair exposed an independent checker defect outside the repository: Vite module real paths did not match the Windows 8.3 TEMP alias. The experiment was stopped; both slots remain spent and invalidated, including an interrupted candidate task. Canonicalizing the checker's root reproduced the expected fail/pass on fresh external-TEMP baseline/reference projects. Remaining slots proceed after that offline gate, without replacing the invalidated pair or adding budget. The ledger retains usage for invalidated tasks; they are not quality failures attributed to a model or a candidate win.

Live mode exercises **direct native continuity only**, with two task turns, matched model/effort, no automatic classifier/reviewer/fallback/repair calls, fresh dedicated projects and alternating arm order. Auto and cross-audit correctness are evaluated separately with deterministic/native fixtures. Aggregate results are published after the bounded run; raw account data and native logs remain excluded.

Retain the locally verified Auto/audit corrections as bounded rule fixes, without claiming live Auto superiority or parity with official apps. The live binary was frozen before final audit-only quota/fallback refinements; those refinements receive separate final-build unit/native verification, not additional paid runs. No performance optimization, provider-wide intelligence gain, two-Claude live acceptance or historical interruption diagnosis is established. Claude live acceptance is deferred until native authentication is usable; no further Claude inference was attempted in this tranche.
